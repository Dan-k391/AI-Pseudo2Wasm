# Compiler completion milestones

These are the implementation prompts and acceptance gates for this work. The
Cambridge 9618 2026 pseudocode guide is the language reference:
https://www.cambridgeinternational.org/Images/697401-2026-pseudocode-guide-for-teachers.pdf

## 1. CAIE conformance

**Prompt:** Exercise every major construct in the guide through the packaged
self-hosted compiler and compare observable results with the seed compiler.
Fix concrete discrepancies in the self-hosted stages. Record coverage and
remaining gaps honestly; do not infer full conformance from a passing sample.

**Gate:** A dedicated conformance suite runs in `npm test`, checks native and
compatibility programs, and documents the guide sections exercised.

The regression matrix in `tests/conformance.test.js` covers guide sections
2–10: primitive types and constants; one- and two-dimensional arrays;
records, enums, pointers, and sets; arithmetic, Boolean, and string
operations; selection and loops; routines and `BYREF`; both file modes;
inheritance; and `INPUT` into compound targets. It compares the packaged
self-hosted output with the seed output and an explicit expected result.
The suite is representative, not a proof that every valid CAIE program is
accepted. Known compiler grammar limits remain listed in `bootstrap/README.md`.

## 2. Compiler-owned diagnostics

**Prompt:** Make live editor diagnostics use the same self-hosted core that
Compile uses. Preserve responsive editing with debounce and stale-result
suppression. Report a useful line and column for source errors and keep the
existing editor underlines, tooltip, and Problems panel in sync.

**Gate:** Tests prove invalid source gives the same error in diagnostics and
Compile, and late results cannot overwrite newer edits.

Live validation now runs the packaged compiler stages in a Web Worker. If
workers are unavailable, the editor uses the same compiler on the main thread.
The latest source snapshot for each file owns its result, and source errors
retain line and column information for the Problems panel and editor tooltip.

## 3. Self-hosted optimization and release mode

**Prompt:** Optimize emitted native WASM inside `bootstrap/native.pseudo`,
without adding a JavaScript compiler pass. Add an opt-in release build for
speed while keeping guarded IDE execution as the default. Check output and
error parity, bootstrap reproducibility, generated byte size, and benchmark
performance before claiming a speedup.

**Gate:** All tests and the byte-for-byte bootstrap pass; representative
benchmarks show the effect of the optimization and release setting.
